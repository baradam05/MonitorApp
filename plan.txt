#### **2) Dependency Injection a rozhraní (Interface)**

**Cíl:** Vysvětlit Dependency Injection (DI) a identifikovat třídy vhodné pro změnu z `abstract class` na `interface`.

**Vysvětlení:**
*   **Dependency Injection (DI)** je návrhový vzor, kde objekt dostává své závislosti (služby nebo objekty, které potřebuje ke své práci) zvenčí, místo aby si je vytvářel sám. Například místo toho, aby si třída `App` sama vytvářela `EmailNotificationService`, je jí tento servis "injektován" při jejím vzniku. To vede k flexibilnějšímu, lépe testovatelnému a udržovatelnému kódu.

*   **Abstract class vs. Interface:** Ano, převedení zbytečně abstraktních tříd na rozhraní (`interface`) je klíčovým krokem k zavedení DI. Rozhraní definuje pouze "smlouvu" (jaké metody a vlastnosti musí třída mít), ale neobsahuje žádnou implementaci. To umožňuje snadno zaměňovat implementace (např. při testování použít "falešnou" notifikační službu).

**Identifikované třídy:**
Prostudoval jsem váš kód a našel jsem tyto hlavní kandidáty pro převod na `interface`:
*   `abstract class Connection` (ve složce `Queries`) -> `interface IConnectionService`
*   `abstract class Notification` (ve složce `Notifications`) -> `interface INotificationService`

Jejich potomci (`SQLConnection`, `ESConnection`, `EmailNotification` atd.) by pak implementovali tato nová rozhraní.

#### **3) Elasticsearch – výchozí index**

**Cíl:** Vyjasnit, kde se má definovat index pro Elasticsearch dotazy.

**Doporučení:**
Máte naprostou pravdu. I když někteří klienti umožňují nastavit výchozí index v připojení, je **mnohem lepší a flexibilnější specifikovat cílový index přímo v dotazu**. To umožňuje jedinému připojení k Elasticsearch klastru dotazovat se na libovolný počet různých indexů, aniž by bylo nutné měnit konfiguraci připojení.

**Plán implementace:**
1.  Upravím DTO objekt pro Elasticsearch dotaz (pravděpodobně `DbQueryDto` nebo specializovaný `EsQueryDto`, který by bylo vhodné vytvořit) tak, aby obsahoval vlastnost `IndexName` (nebo jen `Index`).
2.  Upravím třídu `ESConnectionService` (dnes `ESConnection`), aby při sestavování dotazu použila hodnotu z této nové vlastnosti a cílila tak dotaz na správný index.

#### **5) Dynamické zprávy v notifikacích**

**Cíl:** Navrhnout systém pro generování dynamických zpráv na základě výsledků dotazů pomocí šablon.

**Návrh a Pseudokód:**
Toto je komplexní nová funkce. Zde je detailní návrh, jak by mohla fungovat.

**A. Úprava DTO pro notifikace:**
Do každého DTO pro notifikace ( `EmailNotificationDto`, `SmsNotificationDto` atd.) bychom přidali nové vlastnosti pro šablony:

```csharp
public class EmailNotificationDto : NotificationDto
{
    // ... stávající vlastnosti (To, From, Subject)
    
    // NOVÉ VLASTNOSTI PRO ŠABLONY
    public string MessageHeader { get; set; } // Hlavička zprávy (např. "Dobrý den, našli jsme následující chyby:")
    public string MessageRow { get; set; }    // Šablona pro každý řádek výsledku (např. "Uživatel {Username} narazil na chybu v {Time}.")
    public string MessageFooter { get; set; } // Patička zprávy (např. "S pozdravem, Monitorovací systém.")
}
```

**B. Logika generování zprávy (pseudokód):**
Vytvořili bychom novou třídu nebo metodu, která by byla zodpovědná za sestavení finální zprávy.

```
function GenerateMessageBody(notificationTemplate, queryResults):
    // queryResults je seznam řádků, kde každý řádek je slovník [název sloupce -> hodnota]

    finalMessage = ""

    // 1. Přidat hlavičku (pokud existuje)
    if notificationTemplate.MessageHeader is not empty:
        finalMessage += notificationTemplate.MessageHeader + "\n"

    // 2. Zpracovat řádky
    if notificationTemplate.MessageRow is not empty and queryResults is not empty:
        allRowsText = ""
        foreach row in queryResults:
            // Vzít šablonu pro řádek
            currentRowText = notificationTemplate.MessageRow
            
            // Nahradit zástupné symboly {ColumnName} skutečnými daty
            foreach columnName, value in row:
                placeholder = "{" + columnName + "}"
                currentRowText = currentRowText.Replace(placeholder, value.ToString())
            
            allRowsText += currentRowText + "\n"
        
        finalMessage += allRowsText

    // 3. Přidat patičku (pokud existuje)
    if notificationTemplate.MessageFooter is not empty:
        finalMessage += notificationTemplate.MessageFooter

    return finalMessage
```

**C. Podpora formátování (HTML tabulky):**
Pro kanály jako e-mail, které podporují HTML, by šablony mohly obsahovat HTML tagy.

*   **MessageHeader:** `"<p>Dobrý den,</p><table><tr><th>Uživatel</th><th>Chyba</th></tr>"`
*   **MessageRow:** `"<tr><td>{Username}</td><td>{ErrorMessage}</td></tr>"`
*   **MessageFooter:** `"</table>"`

Výsledkem by byla hezky formátovaná HTML tabulka v e-mailu. Implementace by pak musela zajistit, že e-mail je odesílán jako HTML.
